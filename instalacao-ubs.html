Guia de instalação

Projeto UBS

Sistema de cadastro e agendamento para Unidade Básica de Saúde, com backend Spring Boot, frontend Angular e banco MySQL, todos em contêineres Docker. Este roteiro leva da clonagem do repositório até a aplicação no ar.

Tempo 15 a 25 minutos Maior parte esperando downloads Requer Docker e Node.js

1

Instalar os pré-requisitos

Programa Versão Para quê
Git qualquer recente clonar o repositório
Docker Desktop com Compose v2 executar os contêineres
Node.js 20.19+ ou 22.12+ compilar o frontend Angular

Java e Maven não são necessários: o backend é compilado dentro da própria imagem Docker. Confira a instalação: 

git --version
docker --version
docker compose version
node --version

O Docker Desktop precisa estar em execução antes dos passos 5 e 6.

2

Clonar o repositório

git clone https://github.com/mamazzei-edu/ubs-repo.git
cd ubs-repo
git fetch --all
git switch feat/nginx-usb-8081

Todos os comandos seguintes partem desta pasta, salvo quando indicado o contrário.

3

Criar o arquivo .env

É o passo mais importante. O .env guarda as senhas e por isso não vai para o repositório — sem ele nada funciona. O repositório traz um modelo pronto: 

# Linux / macOS
cp .env.example .env

# Windows
copy .env.example .env

Abra o .env num editor de texto e substitua os quatro valores marcados com ALTERAR. O próprio arquivo explica cada variável.

Quatro armadilhas que derrubam a partida:

  • SECURITY_JWT_SECRET_KEY precisa de no mínimo 64 caracteres aleatórios. Chave curta impede o backend de subir.
  • DB_USER não pode ser root — a imagem oficial do MySQL recusa subir nesse caso.
  • SPRING_DATASOURCE_PASSWORD tem que ser igual a DB_ROOT_PASSWORD: o backend conecta como root.
  • Sem espaços em volta do = e sem aspas nos valores.

Gerar a chave JWT

# Linux / macOS
openssl rand -base64 64 | tr -d '\n='

# Windows PowerShell
-join ((48..57)+(65..90)+(97..122) | Get-Random -Count 72 | ForEach-Object {[char]$_})
4

Ajustar os caminhos públicos

A aplicação responde sob um prefixo, definido por duas variáveis do .env. Os valores padrão são /ubs e /ubs-api; use-os como estão se não houver motivo para mudar.

Se você alterar esses valores, dois arquivos do frontend precisam acompanhar. Eles valem apenas para o modo de desenvolvimento — o contêiner lê os caminhos direto do .env.

frontend/angular.json — com barra no final

"baseHref": "/ubs/",
...
"servePath": "/ubs/",

frontend/proxy.conf.json — sem barra no final

{
  "/ubs-api": {
    "target": "http://localhost:8080",
    "secure": false,
    "changeOrigin": true
  }
}

Os três valores — .env, angular.json e proxy.conf.json — precisam combinar. Divergência entre eles é a causa mais comum de “a tela abre em branco” e “o login não responde”.

5

Compilar o frontend

O contêiner do Nginx copia o resultado da compilação; ele não compila o Angular. Por isso este passo vem antes de subir os contêineres. 

cd frontend
npm ci
npm run build
cd ..

A compilação cria a pasta frontend/dist/frontend/browser. Se ela não existir, o passo 6 falha com erro de COPY. Repita este passo sempre que alterar o código do frontend.

6

Subir a aplicação

docker compose up -d --build

A primeira execução baixa as imagens e compila o backend — pode levar vários minutos. Acompanhe até aparecer Started BackendApplication in … seconds: 

docker compose ps
docker compose logs -f backend

Ctrl+C encerra o acompanhamento sem derrubar os contêineres.

7

Acessar e entrar

Abra o navegador em http://localhost:8081/ubs/, trocando /ubs pelo valor que você usou em FRONT_BASE_PATH. A raiz http://localhost:8081/ redireciona para lá automaticamente.

E-mail
super.admin@email.com
Senha
123456

Esse usuário é criado automaticamente na primeira partida do backend.

Troque esta senha antes de usar o sistema com dados reais. Ela está escrita no código-fonte e é pública.

Comandos do dia a dia

# Parar e religar (os dados do banco são preservados)
docker compose stop
docker compose start

# Derrubar os contêineres, mantendo os dados
docker compose down

# Ver o que está rodando / logs de um serviço
docker compose ps
docker compose logs -f backend

# Depois de alterar o código do FRONTEND
cd frontend && npm run build && cd ..
docker compose build nginx-ubs && docker compose up -d nginx-ubs

# Depois de alterar o código do BACKEND
docker compose build backend && docker compose up -d backend

# Depois de alterar APENAS os caminhos no .env (sem recompilar nada)
docker compose up -d

# APAGAR o banco e recomeçar do zero — perde todos os dados
docker compose down -v

Portas utilizadas

Porta Serviço
8081 Nginx — é por aqui que a aplicação é acessada
8080 Backend Spring Boot
3306 MySQL

Se alguma delas já estiver ocupada — é comum haver um MySQL local na 3306 —, altere o lado esquerdo do mapeamento no compose.yaml: 

    ports:
      - "3307:3306"

Só o lado de fora muda. A configuração do backend continua apontando para mysql_server:3306, que é o endereço interno da rede do Docker.

Se algo der errado

O backend reinicia sem parar

Rode docker compose logs backend e procure:

  • Communications link failure — a SPRING_DATASOURCE_URL não aponta para mysql_server:3306, ou a senha não confere com DB_ROOT_PASSWORD.
  • erro de chave fraca — SECURITY_JWT_SECRET_KEY curta demais.

A página abre em branco, ou os arquivos .js dão 404

Os caminhos não estão combinando. Confira FRONT_BASE_PATH no .env e o baseHref no angular.json, e lembre que a URL precisa terminar com barra: /ubs/, não /ubs.

A tela abre mas o login não responde

Abra o console do navegador com F12. Erro de CORS significa que o endereço usado não está em LISTA_HOSTS. Erro 404 nas chamadas significa que API_BASE_PATH não está combinando entre o .env e o proxy.conf.json.

docker compose up falha no COPY frontend/dist

O passo 5 não foi executado, ou falhou. Rode npm run build dentro de frontend e confira se a pasta frontend/dist/frontend/browser existe.

Porta já em uso

Mensagem bind: address already in use. Veja a seção de portas acima.

Trabalhar no código (opcional)

Para mexer no frontend com recarga automática, sem reconstruir a imagem a cada alteração: 

# Terminal 1 — sobe só o backend e o banco
docker compose up -d backend mysql_server

# Terminal 2 — servidor de desenvolvimento do Angular
cd frontend
npm start

A aplicação fica em http://localhost:4200/ubs/, e o proxy.conf.json encaminha as chamadas da API para o backend na 8080.
